# 작다고 생략하면, 나중에 더 크게 돌아오는 것

작은 프로젝트를 시작할 때 가장 먼저 고민하는 것은 기능이다. 글을 가져오고, 검색하고, 하나를 선택하면 본문을 보여준다. 하지만 기능의 바깥쪽에도 몇 가지 약속이 필요하다.

## 1. 받을 수 있는 입력을 좁히기

글 주소로 쓰는 `slug`는 파일 경로가 아니다. 허용한 이름으로 글 목록을 먼저 찾고, 그 목록에 있는 파일만 읽는다. 사용자가 보낸 문자열을 그대로 파일 경로로 연결하지 않는다.

```js
const post = posts.find((item) => item.slug === slug);
if (!post) return notFound();
return readPost(post.slug);
```

## 2. 실패도 응답의 일부로 다루기

없는 글은 없는 글이라고 알려준다. 내부 파일 경로나 예외 전체를 독자에게 보여줄 필요는 없다. 대신 독자가 할 수 있는 다음 행동, 예를 들면 목록으로 돌아가기를 제공한다.

- 없는 글: 찾을 수 없다는 안내와 목록 링크
- 검색 결과 없음: 필터 초기화
- 서버 오류: 안전한 오류 안내와 다시 시도할 방법

## 3. 읽기와 쓰기를 구분하기

이 블로그의 첫 버전은 읽기 전용이다. 글은 프로젝트 안의 Markdown 파일로 관리하고, 공개 API에서는 수정하지 않는다. 편집 화면이 필요해지는 순간에 인증과 게시 정책을 함께 결정하면 된다.

**기능이 적다는 것과 경계가 없다는 것은 다르다.** 작게 시작하더라도 현재 어디까지 가능한지는 분명하게 남겨두고 싶다.
