# “이제 되네요” 다음에 할 일

오류를 고친 직후에는 같은 동작을 한 번 더 해보게 된다. 이 확인을 반복 가능한 형태로 남겨두면, 다음 수정 때 조금 덜 불안할 수 있다.

## 실패한 상황을 작게 만들기

처음부터 전체 사용 흐름을 모두 자동화하려고 하지 않는다. 문제가 생긴 입력과 기대한 결과부터 한 줄씩 적는다. 예를 들어 존재하지 않는 글 주소로 들어갔을 때 서버 오류가 아니라 찾을 수 없다는 안내가 나와야 한다.

```js
const response = await fetch('/api/posts/missing');
assert.equal(response.status, 404);
```

## 확인한 것과 아직 모르는 것

위 테스트가 통과했다고 해서 모바일 화면이 잘 보인다는 뜻은 아니다. 키보드로 목록을 오갈 수 있는지, 느린 네트워크에서 검색 결과가 뒤섞이지 않는지도 별도의 확인이다.

- 자동 테스트: 상태 코드와 데이터 구조
- 브라우저 확인: 클릭, 이동, 검색, 화면 배치
- 아직 못 한 것: 실제 기기와 운영 환경

## 완료 보고도 작게, 정확하게

“전부 잘 됩니다”보다 **어떤 조건을 확인했고 무엇이 남았는지** 적는 편이 다음 작업에 도움이 된다. 실패 로그는 끝난 기록이 아니라 다음 테스트의 재료가 된다.
