# 작업 기준에서 Review까지

Context는 이번 작업에서 에이전트가 따르는 요청·합의·가정을 보여주는 pane이다. 사용자는 구현 중에 에이전트의 이해를 확인하고 Agent에서 잘못된 전제를 바로잡을 수 있다. 작업 순서를 나열하는 Plan이나 완료 상태를 관리하는 Tasks와 별개다.

## 작업 중의 Markdown

표나 카드 대신 작은 Markdown 문서처럼 제목·짧은 문단·목록으로 쓴다. 이번 구현에 영향을 주는 내용만 포함하며, 없는 항목을 채우려고 계약이나 가정을 만들지 않는다.

- 사용자 요청: 이번 프롬프트나 후속 지시를 어떻게 이해했는지 적는다.
- 참고하는 합의·계약: 실제로 읽은 문서의 상대 경로·항목 또는 사용자가 결정한 대화 내용을 출처로 적는다.
- 에이전트의 가정: 사용자가 확인하지 않은 해석임을 명시한다. 사용자의 침묵은 동의가 아니다.

색상 하나를 바꾸는 작업은 요청 한 줄로 충분하다. 짧은 질문, 상태 확인, 원문 보기, 작업 목록만 갱신하는 요청에는 Context를 강제하지 않는다. 구현을 시작할 때는 관련 자료를 읽고 변경 전에 기준을 공개한다. 기준이 바뀌면 같은 ID로 갱신하고, 필요한 선택은 기존 Input에서 받는다. 별도의 승인 절차를 추가하지 않는다.

Input 선택을 받은 뒤에는 해당 선택과 출처를 같은 기준에 먼저 반영하고 구현한다. `wait` helper는 응답 JSON을 그대로 유지하면서 stderr에 이 갱신 순서를 안내한다. 완료 Review가 선택 전 기준을 보관하지 않도록 실제 AI 검증에서도 선택 전후 Markdown이 달라졌는지 확인한다.

Context는 에이전트가 명시적으로 공개한 이해이며 실제 구현이 계약을 지켰다는 증거는 아니다. 원시 내부 추론·프롬프트 전체·비밀·호스트 경로는 공개하지 않는다. 내용은 기존 텍스트 전용 Markdown 렌더러를 사용하며 HTML을 실행하지 않는다.

## 표시와 수명

- 작업당 하나만 공개한다. 새 작업은 새 ID를 쓰고 작업 중에는 같은 ID로 갱신한다.
- 데스크톱에서 Agent 옆 pane 영역에 표시한다. 첫 공개와 후속 갱신은 Agent나 Input의 포커스를 빼앗지 않는다. 갱신은 사용자가 정한 크기·현재 pane 순서도 유지한다.
- 모바일에서는 작업 기준 탭으로 읽는다. 다른 탭을 읽는 동안 갱신이 와도 강제로 전환하지 않는다.
- 서버가 작업 ID·마지막 변경 시각·진행/종료/중단을 부여한다. 에이전트가 해당 메타데이터를 제출하는 것은 거부한다.
- 다음 작업에서는 기존 artifact와 같이 접힌다. 이전 작업이나 다른 프로젝트의 기준을 새 Review에 자동 연결하지 않는다.

## 완료 시 Review

에이전트가 완료 보고를 제출할 때 Context와 같은 ID로 `kind: review`를 공개한다. 서버는 마지막 Markdown을 Review에 보존하고 UI는 **작업 기준 → Review**로 이어진다. **이 작업의 기준 다시 보기**를 펼쳐 당시 전제와 실제 변경·검증 결과를 함께 읽는다.

다른 ID로 Review를 제출해도 같은 작업의 Context를 대체하며 기준을 보존한다. 중복 pane은 만들지 않는다. 이미 Review로 전환한 기준은 같은 작업에서 Context로 되돌려 수정할 수 없다. Review를 갱신해도 기준 스냅샷을 유지한다.

Review는 실제로 제출된 보고만 표시한다. 보고 없이 작업이 끝나면 Context에 **작업 종료 · Review 미제출**, 중단되면 **작업 중단 · 마지막 기준**을 표시한다. 중단 전에 Review가 제출되었다면 중단 상태를 함께 표시한다. 재시작 시 진행 중이던 저장본도 중단으로 취급한다. 작업 종료나 기준 공개를 검증 통과로 바꾸지 않는다.

실제 명령 종료 코드, 에이전트의 수동 확인, 미검증 사항의 구분은 [기존 Review 규칙](DECISIONS_AND_REVIEW.md)을 따른다. 기준별 적용 결과나 남은 가정은 변경·검증 설명과 주의 사항에 서술한다.

## 에이전트 연동

```json
{
  "type": "pane.upsert",
  "pane": {
    "id": "reply-context-1",
    "kind": "context",
    "title": "작업 기준",
    "content": "## 사용자 요청\n\n- 질문에 답변을 추가합니다. 출처: 이번 요청.\n\n## 에이전트의 가정\n\n- 질문당 답변 하나로 해석했습니다. 사용자 미확인.",
    "size": 1
  }
}
```

이후 같은 ID로 실제 `review` 객체를 제출한다. `workContext`는 서버 전용 필드이므로 event에 넣지 않는다. 새 pane을 만드는 판단과 Markdown 내용은 에이전트 지침에 따라 생성되며, 호스트가 프롬프트를 추측해 만들거나 내부 파일 이벤트를 자동 공개하지 않는다.

리허설에서도 기준 → Input 선택 → 기준 갱신 → 고정 프로세스 → Review 흐름을 확인할 수 있다. 리허설은 실제 AI 구현이 아니며 Review에도 그 범위를 표시한다. 실제 TUI는 새 지침을 포함하도록 에이전트 이미지를 다시 빌드한 뒤 실행해야 한다.
