# 명령 결과를 기다릴 때의 Terminal

일반 설치·빌드·테스트는 `exec`/`run`으로 실행한다. Pado는 **현재 Antigravity가 해당 명령 결과를 기다리는 것이 확인되고, 실제 프로세스도 아직 실행 중일 때** 읽기 전용 Terminal을 연다. 오래 걸린다는 이유만으로 대기를 추측하지 않는다.

```sh
node /opt/pado/present.mjs exec checks --cwd my-app npm test
```

서버 실행 `serve`는 기존처럼 시작 로그를 즉시 열고, 준비된 Browser 옆에도 유지한다. 직접 여는 대화형 Terminal의 동작은 바꾸지 않는다.

## 표시 여부

- native 도구가 결과를 기다리는 동안: 연결된 실제 실행 로그를 표시한다.
- 도구가 백그라운드 작업을 반환하고 에이전트가 다른 일을 하거나 추론하는 동안: 실행 중이라는 사실만으로 새 로그 pane을 만들지 않는다.
- 에이전트가 `Stop(fullyIdle:false)`로 멈추고 백그라운드 결과를 기다릴 때: 같은 작업의 아직 끝나지 않은 실행을 표시한다.
- 내부 파일 읽기·수정·부수적인 확인은 `--quiet`로 실행한다. Input 응답 대기·pane 공개도 대상이 아니다. 특히 공개 모드의 파일 작업도 helper를 사용하므로 `exec`라는 이유만으로 공개하지 않는다.
- 사용자가 로그 자체를 명시적으로 요청했다면 `--show`로 즉시 공개한다. `--quiet`와 함께 쓸 수 없다. 단순히 설치·테스트 로그를 숨기려고 `--quiet`를 사용하지 않는다.

새 로그는 Agent·Context·모바일 탭의 포커스를 빼앗지 않는다. Input이 활성화돼 있으면 대기 로그의 새 공개를 보류한다. 이미 열린 로그는 명령이 백그라운드로 전환되어도 유지하며, 실제 종료 코드까지 기록한다. 사용자가 닫으면 다시 열지 않고 기존 저장 로그만 갱신한다. 다음 turn의 일반 artifact 숨김 규칙은 유지한다.

## 연결과 경계

고정 helper가 현재 루트 대화의 native `run_command`와 자신의 argv를 정확히 대조해 turn token·대화·step을 연결하고, 아직 반환되지 않은 도구의 실제 실행 진입을 확인한다. 컨테이너 안의 관측기가 invocation, 도구 반환, Stop hook과 현재 transcript를 함께 읽어 대기 step만 전달한다. `RUNNING` 기록 하나만으로 도구가 반환됐다고 추정하지 않는다.

호스트는 현재 프로젝트·turn·루트 대화·step·1.5초 이내 관측과 실제 runtime request ID를 함께 확인한다. 프롬프트·추론·도구 인자·native 로그는 대기 snapshot에 포함하지 않는다. 출력은 기존 credential-free 앱 컨테이너의 스트림과 시크릿 필터를 사용한다. 공개 전 버퍼는 최대 60,000자·128개 조각이며, 명령이 먼저 끝나면 뒤늦게 pane을 만들지 않는다. pane 제한에 걸려도 명령을 중단하지 않는다.

현재 자동 연결 범위는 Pado `exec`/`run`을 거친 루트 에이전트 명령이다. 직접 native shell, 여러 도구가 섞여 연결이 모호한 호출, 잘린 명령 인자 등은 추측해서 공개하지 않는다. 서브에이전트의 작업은 기존 Subagent pane을 유지한다. `--quiet`를 고르는 내부 작업 분류는 여전히 에이전트 지침을 따르며 의미를 완벽히 판별하는 보안 분류기가 아니다.

실제 반영에는 새 helper·관측기·hook을 포함한 이미지와 새 서버가 모두 필요하다. 공개 모드에는 갱신된 `public-hooks.json`도 필요하다. 이미 실행 중인 TUI에는 자동으로 새 이미지가 주입되지 않는다.
