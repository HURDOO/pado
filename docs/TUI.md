# 원본 Antigravity TUI 전환

Agent pane을 커스텀 React 채팅에서 **실제 `agy` 대화형 터미널**로 교체했다. 원본 프롬프트, 응답, `/model` 등 슬래시 메뉴, 승인 화면과 진행 출력을 그대로 사용한다. 별도 채팅 입력창이나 재구성한 답변은 실제 실행 모드에 없다.

## 사용

1. WireGuard 내부망에서 `http://<LAN_IP>:4173`을 열고 닉네임으로 입장한다. `<LAN_IP>`는 로컬 설정의 실제 내부 IP로 바꾼다.
2. 손들고 참여하기 → TUI 내부를 눌러 입력 → Enter. 마우스 휠과 터치 스와이프, 모바일의 Esc·Tab·Ctrl·Alt·방향키·PgUp·PgDn·줄바꿈·Enter 보조 키를 사용할 수 있다. Ctrl/Alt를 누른 뒤 다음 키를 입력하면 조합으로 전송하고 자동 해제한다(예: Ctrl → C, Alt → J). 다시 누르면 선택을 취소하고, Ctrl과 Alt를 함께 선택할 수도 있다.
3. 다른 참가자는 같은 TUI 화면과 생성형 pane을 관람한다. 작업 중에는 요청자와 관리자만 입력할 수 있다. 반납·만료 시 이전 입력을 지우고 다음 차례를 연다.

참여 가능한 때만 TUI 화면 아래쪽에 파란색 **손들고 참여하기** 버튼이 떠 있다. 버튼은 터미널 영역 안에 겹쳐 표시되어 화면 높이를 차지하지 않는다. 다른 사람의 발언·작업, 전환, 재연결 또는 요청 처리 중에는 숨긴다. 내 발언 차례에는 남은 시간과 양보 버튼만 작은 줄로 표시하고, 입력 가능 여부는 기존 TUI 상태줄에서 확인한다. pane 제목줄은 최소화하고 중복 부제목·workspace 소개 헤더·하단 안내 footer는 표시하지 않는다.

프로젝트마다 세션 하나를 지속 실행한다. 3개 프로젝트면 TUI 3개가 상주하며 열람/참여 지정 변경으로 종료하거나 재시작하지 않는다. 관리자가 지정한 참여 프로젝트만 입력 가능하고, 나머지는 관리자도 읽기 전용이다. 일반 중단/서버 재시작 뒤에는 해당 프로젝트의 저장된 conversation ID로 이어진다. 관리자 초기화만 해당 대화 연결을 비운다. 작업 파일과 기존 인증 volume은 삭제하지 않는다. [프로젝트 workspace](WORKSPACES.md)를 참고한다.

## 검증 결과

- 타입 검사, 린트, 포맷, production build 통과.
- 단위 테스트 34개 통과. native buffer 재접속, 발언권, hook lifecycle, child hook 분리, 입력 파일, 시작 중 중단, 종료 실패 차단, 발언권 양도 시 입력 초기화를 포함한다.
- 기존 브라우저 회귀 테스트 10개 통과.
- 실제 AI TUI 브라우저 시나리오 2개 연속 통과: 원본 모델 메뉴·공유 관람·권한 거부·재접속·모바일 한글 입력, 생성 Input 답변 → 실제 파일 → 명령 출력 → 관리자 중단·새 TUI 초기화.
- 실제 내부망 HTTP production 화면에서 desktop/mobile Chromium 확인. 한글 입력, 휴대폰 폭 리사이즈, 입력 반납, 기존 보드 보존, JS 오류 없음과 페이지 가로 넘침 없음 확인. 물리 Android 기기에서의 WireGuard 경로·키보드 조합은 사용자의 실기기 확인이 필요하다.

화면 기록은 `test-results/live/` 및 `test-results/native-lan/`에 남겼다. 원본 TUI의 로그인 계정 표시가 포함될 수 있으므로 외부 공유 전에 확인한다. 이전 22시 초안의 headless 테스트 기록과 이번 native TUI 검증을 혼동하지 않는다.

## Subagent TUI

서브에이전트마다 읽기 전용 xterm pane이 하나 열린다. 부모의 원본 CLI와 별도로 자식 CLI를 중복 실행하지 않고, 컨테이너 안에서 실제 자식 대화를 관측해 색상이 있는 터미널 로그로 표시한다. 원본 CLI의 독립 PTY나 대화 입력창은 아니다.

- `READ / LIST / FIND`: 작업 설명, workspace 상대 경로·행 범위와 조회 상태.
- `WRITE / EDIT`: 대상 파일과 실제 수정 결과의 diff 발췌. 실행 전 변경안을 완료된 수정으로 표시하지 않는다.
- `RUN`: 명령 요약, 필터링한 stdout 발췌, 확인된 종료 코드. helper를 쓰면 내부 명령의 종료 코드를 사용하며 알 수 없는 응답은 성공으로 추정하지 않는다.
- `MESSAGE / RESPONSE`: 중간 전달 메시지와 공개 응답. 실제 도구 결과가 오기 전에는 결과 대기로 표시한다.

알려진 도구의 선택된 필드만 읽는다. 내부 추론·사용자/시스템 프롬프트·원시 CLI 진단·전체 도구 인자는 보내지 않으며 제어 시퀀스와 알려진 인증정보 패턴/호스트 경로도 제거한다. 파일 본문 전체는 중계하지 않는다. 명령 스택 트레이스와 민감 경로 조회 결과는 숨긴다. 도구와 결과를 확실히 연결할 수 없는 병렬 기록은 완료로 추정하지 않는다. 출력은 최근 16,000자까지 유지하고, 긴 결과·diff·이전 로그가 생략되면 표시한다. 색상은 클라이언트가 안전한 텍스트에만 추가한다.

실행 hook과 메타데이터 감시가 같은 자식 대화를 동일한 ID로 식별해 중복 pane을 방지한다. 응답 완료/종료 후 3초 뒤 서버가 pane을 닫으며, 늦은 출력은 닫힘 시간을 연장하거나 창을 다시 열지 않는다. 새 작업으로 실제 재개하면 같은 작업 pane을 다시 사용한다.

다음 사용자 turn에서 기존 서브에이전트를 `send_message`로 재사용해도 로그를 표시한다. 생성 시점뿐 아니라 현재 turn의 자식 실행 hook을 확인하며, 자식의 이번 실행 시작 step 이후만 읽어 이전 작업 로그를 섞지 않는다. 과거 메타데이터나 다른 turn의 hook만으로는 출력을 공개하지 않는다.

## 경계

신뢰하는 내부망 사용자용이다. 원본 TUI에는 로그인 계정 표시와 도구 출력도 보인다. 비밀번호/API 키를 입력하지 않는다. 외부 공개용 credential·egress 격리와 장시간 운영 검증은 완료 범위가 아니다. 세부 구조와 실행 방법은 [연동 안내](AGENT.md)를 참고한다.
