# 프로젝트 workspace와 창의 흐름

## 자유로운 열람, 하나의 참여 프로젝트

누구나 데스크톱 왼쪽 목록이나 태블릿·모바일 상단 선택기에서 프로젝트를 열람한다. 파란 선택 표시는 **내가 보는 프로젝트**, 초록 `참여` 표시는 **관리자가 지정한 참여 프로젝트**다. 열람 선택은 탭의 sessionStorage에만 저장하여 같은 관객의 다른 탭도 서로 간섭하지 않는다. 다른 곳을 선택하지 않은 탭과 `참여 프로젝트로 돌아가기`를 누른 탭은 관리자의 지정을 따라간다.

비활성 프로젝트는 관리자도 읽기 전용이다. TUI 입력·크기 변경·손들기·Input/시크릿 응답·공유 창 조작·중단/초기화를 서버에서 거부한다. 관리자는 읽기 전용 안내줄의 `참여 프로젝트로 지정`을 별도로 눌러 참여 대상을 바꾼다. 현재 참여 프로젝트의 turn·발언권·Enter 직후 native hook 대기·처리 중인 변경 요청이 있으면 지정을 바꿀 수 없다. 이때도 다른 프로젝트 열람은 가능하다.

프로젝트 생성·이름 변경은 관리자만 가능하다. `만들고 열기`는 새 프로젝트를 내 화면에서 열 뿐 참여 지정을 바꾸지 않는다. 새 프로젝트는 빈 폴더로 시작하며 기존 파일을 복사하거나 삭제하지 않는다. 최대 12개이고 삭제 기능은 없다. 상주 세션 수에 따라 메모리가 늘어나므로 12개가 모두 저비용이라는 뜻은 아니다.

- 기존 작업은 처음 `기존 프로젝트`로 등록했고, 현재 시연 이름은 `해커톤 데스크`다. 이름을 바꿔도 ID와 `.pado/workspace` 경로는 유지한다.
- 새 작업 파일은 `.pado/projects/<id>/workspace`에 저장한다. 프로젝트 이름으로 호스트 경로를 만들지 않는다.
- 각 프로젝트의 공개 창·최근 대화 메시지·숨겨진 artifact·원본 TUI conversation 식별자·마지막 정상 앱 실행 명령은 workspace 밖의 비공개 메타데이터로 저장한다. 재시작 후에도 복원한다. 비밀번호/API 키는 이 메타데이터에 넣지 않고, [시크릿 Input](SECRETS.md)의 별도 프로젝트 저장 파일에 보관한다. 앱 실행 명령에는 주입할 변수 이름만 저장한다.
- 원본 TUI·StageStore·앱 runtime·gateway는 프로젝트마다 독립적으로 상주한다. 3개 프로젝트면 TUI 3개이며, 앱이 등록된 프로젝트는 자신의 앱 서버도 유지한다. 서버 시작 시 각 TUI와 마지막 정상 앱 실행 명령을 병렬 복원한다. 열람/참여 지정을 바꿔도 epoch·대화·앱 프로세스는 유지된다. 자동 복원은 새 Terminal pane을 열거나 화면 focus를 빼앗지 않는다. 명시적 중단 이후에는 해당 프로젝트에서 손들기/관리자 조작으로 TUI를 다시 시작한다.
- TUI는 해당 프로젝트의 정확한 conversation ID로 이어진다. 모든 컨테이너의 경로가 `/workspace`이므로 경로 기반 `--continue`는 사용하지 않는다. [공식 resume 문서](https://www.antigravity.google/docs/cli/commands/resume).
- ID뿐 아니라 CLI의 `conversations` SQLite 데이터, `brain`, 비인증 `cache`, `.gemini/config/projects`의 프로젝트 레코드도 프로젝트의 비공개 `cli/`에 보존한다. 인증 토큰·settings·hooks는 계속 임시 프로필에만 두며 다른 프로젝트/앱 컨테이너에는 이 대화 디렉터리를 마운트하지 않는다. 원본 `/fork`·`/resume`으로 선택한 대화도 종료할 때 반영한다. ID만 저장한 첫 실제 검증은 대화를 복원하지 못했으므로 이 데이터 보존을 추가했다.
- 관리자 초기화는 **현재 프로젝트의** 창·저장된 창·대화 연결을 비운다. 작업 파일과 다른 프로젝트는 유지한다. 명시적인 중단·초기화는 앱 자동 복원 명령도 비운다.

## 에이전트가 관리하는 창

상단 `+`로 사용자가 직접 열거나 복원한 pane은 다음 turn의 자동 접기에서 제외한다. 현재 발언자/작업 요청자와 관리자가 공유 창을 추가·닫기·크기 변경할 수 있으며, 관객은 열람만 한다. 직접 여는 Terminal은 프로젝트당 최대 3개의 별도 Docker 셸로 실행한다. 닫기나 중단 시 프로세스를 종료하고 서버 재시작 후에는 명시적으로 다시 시작한다. [수동 pane 안내](PANES.md#사용자가-직접-여는-pane).

| 순간                 | 화면                                                          |
| -------------------- | ------------------------------------------------------------- |
| 새 turn 시작         | 이전 artifact를 접고 Agent에 집중. 파일과 실행 중인 앱은 유지 |
| 내부 구현·짧은 답변  | 기본 TUI만 사용. 도구를 썼다는 이유로 창을 만들지 않음        |
| 선택이 필요함        | Input을 열고 실제 답변을 기다림                               |
| 실제 작업 상태 갱신  | 같은 Tasks ID를 갱신하고 크게/앞으로 표시                     |
| 웹 결과가 준비됨     | Browser를 크게 맨 앞에, 보조 Tasks는 작게                     |
| 다른 프로젝트 열람 | 내 탭만 해당 프로젝트의 창·파일·대화·실행 앱을 읽기 전용으로 표시 |
| 참여 프로젝트 지정 | 새 지정 프로젝트만 입력 허용. 이미 다른 곳을 열람하던 탭은 그곳을 유지 |

서버는 turn 시작의 접기와 에이전트가 보낸 창 조작을 적용한다. 어떤 결과가 중요한지는 에이전트가 판단한다. **모든 turn 끝에 Browser를 강제로 띄우는 규칙은 아니다.** 앱과 관계없는 짧은 답변이면 Agent만 남는 것이 맞다.

`pane.upsert`는 같은 ID의 내용을 갱신하고 맨 앞으로 옮긴다. `pane.focus`는 앞으로 옮기고 최소 size 2로 확대한다. `pane.show`는 닫거나 접어둔 artifact를 내용 그대로 복원하고 앞으로 옮긴다(선택적 size 1~3). 최근 24개의 artifact를 저장한다. Input과 Subagent는 복원 대상이 아니다. 실제 파일 내용이 바뀌면 `show`가 아니라 원문을 읽어 `upsert`해야 한다. 숨긴 Terminal의 배경 로그가 창을 다시 열거나 포커스를 빼앗지 않는다.

`serve app ...`는 이미 ID `app`인 Browser를 만든다. 같은 서버에 새 ID의 Browser를 하나 더 만들지 않는다. 모바일은 동일한 focus 이벤트로 활성 탭을 바꾼다. 관객이 탭만 바꾸는 것은 자기 화면에만 적용된다.

## 연결·경계

프로젝트마다 gateway 포트 4개를 별도로 배정한다. 기본값은 첫 프로젝트 4273~4276, 다음 4277~4280 순서다(최대 4320). 각 프로젝트 gateway를 함께 열고 앱 Docker 포트는 여전히 loopback 전용이다. 다른 포트 origin으로 저장소와 연결을 구분한다. SSE 상태와 TUI 출력도 구독한 프로젝트만 전달한다.

참여 프로젝트가 아닌 앱은 GET/HEAD/OPTIONS만 허용하고 POST/PUT/PATCH/DELETE 및 WebSocket을 거부한다. 참여 지정이 바뀌면 기존 변경 요청/WS 연결도 닫는다. 따라서 비활성 앱의 실시간 WS/HMR은 연결되지 않고 일반 조회·검색·페이지 이동은 가능하다. 이는 **HTTP 메서드 기반 읽기 전용**으로, 잘못 설계된 GET의 부작용이나 앱 자체 배경 작업을 동결하는 보장은 아니다. 생성 HTML Browser는 입력/버튼/폼을 비활성화하지만 임의 JS의 로컬 애니메이션까지 멈추지는 않는다.

쿠키는 포트로 분리되지 않으므로 gateway는 서버 쿠키 이름을 프로젝트별로 구분하고 HttpOnly로 강제한다. Pado 인증 및 다른 프로젝트 쿠키를 앱에 넘기지 않는다. `document.cookie`에 의존하는 앱 상태는 현재 지원하지 않으며 서버 세션 또는 프로젝트별 origin의 localStorage를 사용한다. 같은 관객 모두가 프로젝트를 열람하는 내부망 제품이며 사용자별 비공개 프로젝트나 외부 공개 멀티테넌트 보안을 제공하는 것은 아니다.

## 준비된 프로젝트

내부망 시연 베이스는 해커톤 데스크, 아이디어 보드, 개발자 블로그의 세 workspace다. 해커톤 데스크의 기존 데이터와 사용자가 정한 다음 작업은 유지한다. 초기 아이디어 보드는 별도 workspace에 원본 그대로 복사하며, 원래 위치의 파일은 보존 자료로 남긴다. 블로그와 아이디어 보드는 별도의 대화·파일·Tasks·Browser를 가진다.

아이디어 보드는 정적 화면 내 상태로, 새로고침/프로젝트 왕복 시 조작이 초기화되며 다른 관객의 앱 데이터와 동기화되지 않는다. 블로그는 실제 Node 서버에서 Markdown 글을 읽고 검색하는 앱이다. 두 프로젝트 모두 미래 작업의 다음 순서는 아직 선택하지 않았다.
