# 비교해서 결정하고, 근거로 검토하기

Pado의 역할은 창 종류를 늘리는 것이 아니라 사용자의 판단·결과 확인 부담을 줄이는 것이다. 비교 선택은 기존 Input의 구조화된 표현이고, Review는 의미 있는 변경의 결과를 검토할 때 쓰는 새 artifact pane이다. Browser 요소 클릭/지정 기능은 이번 범위에 포함하지 않는다.

## 시각적 비교 Input

- 에이전트가 2–4개의 안을 만든다. 각 안에는 실제 차이가 보이는 HTML/CSS 미리보기, 이점, 고려할 점이 필요하다.
- 선택지를 누르는 것만으로 제출하지 않는다. 추가 요청을 적고 **이 안으로 진행**을 누르면 실제 대기 중인 에이전트에 `{optionId, note}`가 전달된다.
- 요청자와 관리자만 제출한다. 관객은 같은 제안을 읽고, 서버는 선택 ID·필드·길이·중복 제출을 검증한다.
- 미리보기는 적용 전의 제안이다. 스크립트·네트워크·상위 페이지 접근이 제한된 비대화형 opaque iframe에서 표시한다. 선택 컨트롤은 Pado가 제공한다. 기존 자유 HTML Input도 그대로 지원한다.
- 화면을 복구하거나 선택지를 고치는 동안에는 같은 Input ID를 쓰되, 새 결정에는 새 ID를 쓴다. 선택 후 Input을 닫고 실제 선택에 따라 구현한다.
- 모바일에서는 한 열로 스크롤하고 확인 버튼은 아래에 유지된다. 데스크톱은 pane 폭이 충분할 때 두 열이다.

예시 요청:

> 질문 목록을 카드형과 컴팩트 목록형으로 비교해서 내가 고르게 해줘. 시각적인 예와 장단점을 보여주고, 선택 확인 전에는 적용하지 마. 고른 뒤에는 실제 앱에 적용해줘.

## Review

구현 중에는 [작업 기준 Context](WORKING_CONTEXT.md)에서 요청·합의·가정을 Markdown으로 확인한다. 완료 Review는 그 pane을 이어받고 **이 작업의 기준 다시 보기**에 마지막 기준을 보존한다. 기준의 출처와 실제 구현 검증은 별개이며, 이전 작업의 기준은 자동 연결하지 않는다.

변경 요약·사용자에게 달라진 점·관련 파일·검증 항목·남은 확인을 한 화면에서 읽는다. 코드 편집기, 적용 승인, 되돌리기 또는 테스트 실행 버튼은 아니다. 새 turn에서는 다른 artifact와 함께 접히고, 프로젝트 안에서 같은 ID로 다시 열거나 갱신할 수 있다.

검증 항목은 세 상태를 구분한다.

| 표시   | 의미                                                               |
| ------ | ------------------------------------------------------------------ |
| 통과   | 실제 명령 종료 0, 또는 근거를 동반한 에이전트의 수동 확인 보고     |
| 실패   | 실제 명령의 nonzero 종료, 또는 구체적인 실패 관측 보고             |
| 미검증 | 아직 확인하지 않았거나 실행 근거를 연결하지 못함. 종료 불명도 포함 |

`present.mjs exec`의 응답에는 `runId`가 들어간다. 에이전트가 현재 turn의 실제 결과를 참조하면 서버가 종료 코드·관측 시각을 붙이고 상태를 결정한다. 조용히 실행한 `--quiet` 결과도 연결할 수 있으며 로그 pane을 억지로 띄우지 않는다. 서버가 관측하지 못한 ID, 이전 turn의 결과는 새 검증의 통과 근거가 될 수 없다. 저장된 Review는 원래 시각과 결과를 보존한다.

`runId` 없는 수동 확인은 **에이전트 보고 · 자동 실행 근거 없음**으로 표시한다. 실제 명령이 종료 0인 것과 특정 사용자 시나리오가 정말 검증된 것은 다르다. 한 빌드 성공을 여러 사용자 흐름의 통과로 부풀리지 않도록 에이전트 정책과 화면에서 이 경계를 알린다. 검증 항목이 비어 있어도 전부 통과로 해석하지 않는다.

실패·미검증 항목에 허용된 앱 포트와 상대 경로를 연결하면 **재현 화면 보기**로 내 화면에서 실제 앱을 열 수 있다. 공개된 Review의 재현 포트만 gateway가 허용한다. 기존 Browser를 닫아도 공개 Review가 있으면 열 수 있지만 앱을 자동 시작하지는 않는다. 다른 관객의 배치를 바꾸지는 않으며 앱 조작은 실제 공유 데이터에 영향을 줄 수 있다. 외부 URL이나 호스트 임의 포트는 허용하지 않는다.

예시 요청:

> 구현한 변경점과 실제 검증 결과를 보여줘. 성공한 명령, 실패한 명령, 아직 못 해본 시나리오를 구분하고 실패나 미검증 항목에는 재현 화면을 연결해줘.

## 주의

모든 pane과 추가 요청은 공유 stage에 공개된다. 비밀번호, API 키, 호스트 경로나 비공개 진단을 넣지 않는다. 화면 미리보기는 작동하는 앱이나 실기기 테스트 증거가 아니다. 최종 결과는 실제 Browser에서 확인한다.
