# 어떤 때 어떤 pane이 열리나

Pado는 단어를 감지해 정해진 창을 띄우는 방식이 아니다. **지금 사용자가 확인·판단·입력·체험할 대상**을 에이전트가 판단하고 presentation 이벤트를 보낸다. 아래는 현재 정책이며 AI 판단이 매번 동일하다는 보장은 없다. 내부 파일 읽기나 명령 실행 자체는 새 pane을 여는 조건이 아니다. Terminal은 예외적으로 현재 에이전트의 검증된 명령 결과 대기와 실제 실행을 연결해 열 수 있다.

| Pane     | 열리는 상황                                                                | 해커톤 데스크에서 해볼 요청                                                                |
| -------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Agent    | 대화·간단한 답·내부 구현 과정. 기본 원본 TUI                               | “지금 질문은 모두에게 공개되는 구조야? 짧게 답해줘.”                                       |
| Subagent | 실제 자식 에이전트 호출 시 자동으로 열리고 작업 종료 3초 뒤 닫힘           | “서브에이전트에게 접근성 검토를 맡기고 실제 결과를 정리해줘.”                              |
| Tasks    | 작업 목록, 완료/진행/남은/보류 상태, 다음 작업, 우선순위를 확인하거나 변경 | “hackathon-ops의 남은 작업과 보류한 작업을 보여줘. 다음 할 일이 지정돼 있는지도 확인해줘.” |
| Context  | 구현 중 참고하는 사용자 요청·기존 합의·에이전트 가정을 Markdown으로 공개   | “기존 공개 정책은 유지하면서 질문에 답변 기능을 붙여줘.”                                   |
| Docs     | 나란히 두고 검토할 명세·정책·비교·결정 기록·공유 보고서                    | “질문 공개 정책의 선택지와 장단점을 팀과 볼 짧은 문서로 정리해줘.”                         |
| Input    | 사용자 값이나 선택이 있어야 다음 단계로 갈 수 있음. 실제 응답을 기다림     | “공개 범위를 내가 고를 수 있게 해줘. 선택 전에는 적용하지 마.”                             |
| Review   | 의미 있는 구현의 변경점·실제 검증 결과·미검증 사항을 함께 검토             | “바뀐 점과 테스트 결과를 보여줘. 실패와 아직 못 해본 것도 구분해줘.”                       |
| File     | 실제 파일 원문이나 코드/diff를 직접 검토                                   | “api.ts의 팀 중복 검증 부분을 원문으로 보여줘.”                                            |
| Terminal | 검증된 명령 결과 대기, 명시적 로그 요청, 서버 시작의 실제 출력·종료 상태   | “API 테스트를 실행하고 실제 결과와 종료 코드를 보여줘.”                                    |
| Browser  | 사용자가 직접 사용해 볼 웹 결과가 준비됨                                   | “해커톤 데스크를 실행해서 팀 등록과 질문 접수를 해볼 수 있게 해줘.”                        |

## 사용자가 직접 여는 pane

오른쪽 위 `+`에서 새 Terminal, 실행 중인 앱을 보는 Browser, 이전에 공유된 Docs·File·Tasks·Context·Review·실행 로그를 선택한다. 저장된 pane은 공개 당시 내용으로 다시 열며 프로젝트 파일을 자동으로 다시 읽지는 않는다. Input과 Subagent는 다시 열기 대상이 아니다.

참여 프로젝트의 관리자 또는 현재 발언자/작업 요청자가 추가·닫기·크기 변경·포커스를 조작한다. 관객은 함께 보고 모바일 탭을 자유롭게 전환한다. 직접 연 pane은 다음 turn 시작 때 자동으로 접지 않으며, 에이전트의 명시적인 닫기와 전체 초기화는 적용된다. 공유 artifact는 기존과 같이 최대 6개다.

직접 여는 Terminal은 실제 실행 모드에서 사용할 수 있는 대화형 bash 셸이다. 프로젝트의 `/workspace`를 공유하지만 Agent 인증·bridge·프로젝트 시크릿·호스트 환경변수는 받지 않는 별도 Docker 컨테이너에서 실행한다. 입력, 붙여넣기, Ctrl+C, 모바일 보조 키와 PTY 크기 변경을 지원하며 출력은 참여자에게 공유된다. 프로젝트당 최대 3개를 동시에 실행할 수 있다. 닫기·관리자 중단·초기화·서버 종료는 셸 프로세스도 종료한다. 서버 재시작 후에는 pane만 복원하고 `터미널 다시 시작`으로 새 셸을 연다. 에이전트의 기존 실행 로그 Terminal은 계속 읽기 전용이다.

Browser는 관리되는 앱 서버의 허용된 포트(3000, 3001, 5173, 8080)와 경로만 선택한다. 직접 연 셸의 서버 포트를 외부에 공개하지 않으므로 앱 미리보기는 에이전트가 관리되는 앱 실행 기능으로 시작한 서버에 연결한다. 리허설에서는 임의 셸 실행 없이 기존 공개 pane 다시 열기만 지원한다.

## 명령 대기 Terminal

명령 대기 Terminal의 세부 조건과 내부 파일 작업·Input·백그라운드 실행의 구분은 [대기 Terminal 안내](WAITING_TERMINALS.md)를 따른다. 서버 실행 로그와 직접 여는 셸은 기존 규칙을 유지한다.

## Subagent의 수명

서버가 검증한 자식 호출마다 별도 pane이 열린다. 준비·진행·응답 완료·종료·오류를 구분하며, 작업이 끝나면 3초 동안 종료 상태를 보여준 뒤 모든 관객 화면에서 함께 닫힌다. 그 사이 같은 자식이 다시 작업하면 닫힘을 취소한다. 부모 작업 중단·실패 시 남은 자식 pane도 종료 처리하며, stage 초기화는 즉시 제거한다. 위임 등록이나 실행 종료만으로 결과의 성공을 보장하지 않는다.

이름과 상태만 표시하고 내부 프롬프트·대화 식별자·로그·호스트 경로는 추가하지 않는다. 일반 artifact pane 6개와 별도로 최대 8개를 표시한다. 관리자의 닫기·크기 변경·포커스와 모바일 탭 전환을 지원한다. Input 응답을 기다리는 동안에는 새 자식 pane이 입력 포커스를 빼앗지 않는다. Subagent는 서버 관리 pane이므로 `pane.upsert`로 만들거나 덮어쓸 수 없다.

## Tasks의 의미와 경계

- `[-] 진행`, `[>] 다음`, `[ ] 대기`, `[~] 보류`, `[x] 완료`를 별도 상태로 표시한다. 체크박스를 누르는 편집기가 아니라 공개된 작업 목록의 읽기 전용 보기다.
- 실제 프로젝트 TASKS/backlog를 읽어 공개하고 출처를 subtitle에 적는다. 없는 작업·완료 사실을 지어내지 않는다. 계획 작성을 요청한 경우에만 제안임을 명시한 초안을 만든다.
- `[>]`가 없으면 “선택된 다음 작업 없음”이다. 첫 대기 항목이 자동으로 다음 일이 되지 않는다. 두 개 이상이면 충돌을 표시하며 임의로 하나를 고르지 않는다.
- “작업해줘”, “버튼 색을 바꿔줘”, “방금 테스트 끝났어?”만으로는 필요하지 않다. 반면 “작업 진행 상황/남은 일”처럼 **프로젝트 작업 목록을 검토하는 의도**면 짧은 요청이어도 Tasks를 연다.
- 보기 요청은 문서 수정이나 구현 허가가 아니다. “운영자 답변을 다음 작업으로 지정해줘. 구현은 하지 마”라면 원문과 같은 Tasks pane을 갱신하되 구현을 시작하지 않는다.
- 우선순위를 결정해야 한다면 Tasks는 현황, Input은 선택을 담당한다. 선택 결과가 실제 작업 문서에 반영된 뒤 같은 Tasks pane을 갱신한다.
- 목록은 에이전트가 명시적으로 공개한 스냅샷이다. 파일 감시로 자동 생성되지 않는다. 관련 상태를 바꿨다면 열린 Tasks를 다시 공개하고 중복 pane은 만들지 않는다.

## 시각적 선택과 결과 검토

구현할 때에는 [작업 기준](WORKING_CONTEXT.md)을 먼저 공개하고, 중요한 전제가 바뀌면 같은 pane의 Markdown을 갱신한다. 계획표를 만들거나 작은 작업의 모든 칸을 채울 필요는 없다. 갱신은 읽던 pane의 포커스를 바꾸지 않는다. 완료 시 같은 작업의 Review로 전환하며 마지막 기준을 펼쳐볼 수 있다. Review 없는 종료와 중단은 통과로 표시하지 않는다.

Input은 자유 HTML 폼 외에 **시각적 비교 선택**을 지원한다. 에이전트가 2–4개 안의 미리보기와 장단점을 만들고, 요청자가 안을 고른 뒤 확인하면 구현을 이어간다. 단순 클릭이나 선택 전에는 적용하지 않는다. 예: “모바일 질문 목록을 카드형과 목록형으로 비교해서 고르게 해줘.”

Review는 변경 요약, 관련 파일, 통과·실패·미검증, 남은 확인을 보여준다. 현재 turn의 실제 exec runId를 연결한 결과에는 서버가 확인한 종료 상태를 붙이고, 수동 확인 보고는 별도 출처로 표시한다. 필요한 항목에서는 실행 중인 앱의 재현 화면을 열 수 있다. 짧은 대답이나 작업 목록만 갱신하는 요청에는 Review를 강제하지 않는다. [동작과 경계](DECISIONS_AND_REVIEW.md)를 참고한다.

## 한 요청에 꼭 하나만 열리지는 않는다

새 turn이 시작되면 이전 창은 접고 Agent에 집중한다. 결과가 준비되면 에이전트가 필요한 창만 다시 열며, `pane.show`는 저장된 내용을 복원하고 `pane.focus`는 앞쪽으로 이동·확대한다. Tasks를 갱신한 경우에도 같은 ID를 다시 전면에 보여준다. 창을 닫아도 파일·앱 데이터는 삭제하지 않는다. 프로젝트별 전환과 전체 수명은 [workspace 안내](WORKSPACES.md)를 참고한다. 기존의 “다음 turn에도 모든 결과 창 유지” 정책을 대체한다.

“남은 일을 보고 다음 기능을 골라서 구현하자”는 Tasks → Input → 구현 → Browser로 이어질 수 있다. 결정 근거를 따로 보관할 필요가 있을 때만 Docs를 더한다. 설치·빌드·테스트의 결과를 기다릴 때 Terminal이 열리며, 내부 파일 작업이나 이미 완료된 빠른 실행에는 강제하지 않는다. 검토가 끝난 임시 pane은 닫거나 줄이고 유용한 결과는 보존한다.

Tasks/Docs/File을 모두 띄워 같은 목록을 반복하지 않는다. 파일 자체를 정확히 검토하라고 한 경우에는 Tasks 대신 File이 맞다. 비밀번호·API 키는 [시크릿 Input](SECRETS.md)으로만 받는다. 생성 HTML 폼은 사용하지 않고, 에이전트에는 변수 이름과 설정 여부만 반환한다.
